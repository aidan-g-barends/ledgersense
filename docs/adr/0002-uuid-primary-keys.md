# ADR 0002: UUID primary keys

**Status:** Accepted
**Date:** 2026-10-08

## Context
Record IDs appear in API URLs (e.g. `/api/transactions/{id}`). Sequential integer IDs
are guessable, which turns any missed authorization check into a data leak (IDOR),
and they reveal business volume (how many transactions or customers exist).

## Decision
All primary keys are `UUID`, generated by PostgreSQL via `gen_random_uuid()` (v4).

## Consequences
- IDs cannot be enumerated or used to infer volume.
- Authorization (org scoping on every query) remains the primary protection;
  UUIDs are defence in depth, not a substitute.
- 16 bytes per key instead of 8, and random insert order in indexes. Negligible
  at LedgerSense's expected scale.
- Future option: switch to time-ordered UUIDv7 (native in PostgreSQL 18) if
  index performance ever becomes a measured problem.
